# 保持 CellChat 计算定义的大规模、低内存通讯推断

## 研究范围

本实验从 GitHub `wyuanhang03-web/CellChatPy` 的提交
`986bf7ef909f1e15059aad8a9a9ee31ac675ffc3` 开始。`upstream/` 是冻结的
发布源码，`development/` 是开发版本。优化对象是
`compute_communication_probability` 的**细胞群层面推断**；本项目没有
改变 CellChat 的生物学模型、数据库、平均表达定义、置换次数或显著性规则。
空间 spot 层面函数和其他下游分析保持原有实现。

这是一项可复现的算法工程研究原型。创新性仍需要与现有稀疏顺序统计和
置换算法文献进一步比较；不能仅凭本次加速结果宣称首创或保证发表。

## 计算契约

1. 在所有选定 signaling genes 上计算全局最大值并归一化。
2. 按原 categorical 顺序计算细胞群表达统计量。缺失群标签不参与当前组
   统计，但该细胞仍保留在完整标签置换和 population size 分母中。
3. 保留复合物可用亚基的几何均值、共受体、激动剂、拮抗剂、Hill 函数、
   population size 和空间/接触约束的原公式及必要的浮点运算顺序。
4. 随机化细胞群标签，表达矩阵固定；同一 seed 产生与 upstream 相同的
   NumPy 历史 RNG 置换序列。提供外部置换时逐列验证并原样使用；内容为
   整数的浮点数组也按列检查和转换，避免全矩阵验证暂存。
5. P 值仍为严格超越计数 `sum(P_boot - P_observed > 0) / B`；不加入
   epsilon，不改成 `>=`，不加入加一校正。原概率为零时 P 值为一。
6. 保留公开 network 存储、参数及下游 API。执行信息另存
   `cellchat.settings['execution']`。

## 三项计算重组

### 静态依赖裁剪

根据实际候选 LR、复合物、共受体、激动剂、拮抗剂，预先构造基因依赖闭包。
只计算这些基因的群体统计。**归一化最大值在裁剪前计算**，因此未参与当前
LR 的高表达基因仍会正确影响尺度。相同复合物与辅因子表达在每次置换中
仅解析一次，复用结果而不是重复进行 pandas 查表。

### 可复用稀疏顺序统计

对每个基因的非零表达值排序一次，并保存相应 cell indices。置换只改变
这些细胞所属的群体，因此每个群体对应的非零表达仍是该全局有序序列的
一个有序子序列，不必重新排序。

每次置换按群体计数非零条目、缺失值与隐式零。完整排序向量中的隐式零
形成负值与正值之间的虚拟区间。triMean 只需要 Q1、Q2、Q3 的六个端点秩，
因而对排序非零序列线性扫描即可取得所有端点，再采用 NumPy 同样的
线性插值分支。median 单独采用一或两个中位值的原计算方式。

零值无需物化；显式零等同隐式零；重复 sparse indices 先求和；显式 NaN
按 upstream 的 reducer 规则排除。Numba 编译不使用 fastmath，保留纯 Python
正确性回退。首次编译耗时属于冷启动成本，基准需明确是否包含。

若有效基因数为 G、细胞数为 N、群体数为 K、非零元素数为 Z，排序准备
约为 `sum_g O(z_g log z_g)`，随后每次稀疏统计为 `O(Z + G*K + N)`。
它避免每次扫描全部隐式零和重复分位数选择。实际收益依赖稀疏度和规模，
不能把单个算子的倍数当作整个工作流的倍数。

### 流式置换和交互分块

每次只生成一个长度 N 的置换，计算一份 G×K 群体统计，并按 LR 块计算
K×K 概率矩阵，仅累计超越次数。内部不保存 N×B 置换矩阵、B×G×K
平均表达或 B×LR×K×K 概率张量。

公开结果仍需要 `O(LR*K^2)` 存储，这一输出成本没有消失。临时 LR 张量
由 `lr_batch_size` 限定；密集输入及截尾均值/阈值均值采用
`gene_batch_size` 限定的回退计算，保留标量求和/partition 顺序。

上述 `O(Z + G*K + N)` 统计成本仅对应稀疏 triMean/median 路径；密集及
均值回退仍需访问实际群体表达向量。裁剪前，提取和归一化会暂存全部
signaling 表达，其非零条目数可能远大于裁剪后的 Z；密集输入还会产生
全表达归一化副本。这里的“低内存”主要是避免随置换次数增长的内部存储，
不是忽略预处理峰值或原始表达矩阵。外部置换逐列的唯一性验证还包含
`np.unique` 的排序成本，不能直接套用内部随机置换的线性时间界限。

此外，upstream 在推断末尾构造了一个未存储也未返回的长格式表。新引擎
省去这段无输出副作用的构造；用户请求的交互表仍通过现有公开接口生成。

## 实验与解释边界

- 独立回归：动态加载冻结源码，而不是只比较新程序内部的两个分支。
  概率报告绝对/相对误差，P 值和显著性判定要求精确一致。
- 教程：核对 Read the Docs 公开 notebook 与固定源码，完整重新执行。
  数据路径、运行环境及必要的文档断言修订单独记录，不跳过失败 cell。
- 大数据：真实数据与合成数据分开报告。候选筛选固定的推断核计时不能
  宣称是包含下载、预处理、差异基因、可视化的端到端工作流加速。
- 性能：记录独立进程、线程数、版本、输入维度、置换次数、墙钟时间和
  峰值 RSS。超时或内存受限只报告界限，不伪造完成时间/准确性。
- 正确性测试不是生物学验证；保留旧模型定义也不等于解决旧模型的统计
  或生物学局限。零 P 值的原始语义在本项兼容性研究中有意保留。

## 测试中发现的独立兼容性修复

- Visium 教程原有手工验证使用 `p > 0.05`，与包内保留 `p < 0.05`
  的规则不一致。执行版仅将这个断言中的过滤改为 `p >= 0.05`，两引擎
  应用同一记录在案的修订；不改变推断或聚合函数的阈值定义。
- H5AD 保存/加载可能将字典键按字母排序，使 LR 张量轴顺序与 interaction
  表错位。开发版网络显式保存 `matrix_order`，旧 LR 网络则从 interaction
  名称恢复顺序；spot 网络也按 interaction 元数据恢复对应关系。
  此项是存储可靠性修复，不计为加速算法贡献。旧 pathway 文件若未保存
  顺序且没有对应元数据，不能凭空恢复其历史插入顺序；按名称的矩阵不变。

## 使用

```python
import CellChatPy as cc

# 其余准备步骤沿用原教程。默认启用新引擎。
cellchat = cc.compute_communication_probability(
    cellchat,
    engine="streaming",
    n_boot=100,
    seed_use=1,
    gene_batch_size=64,
    lr_batch_size=64,
)

# 同一开发包保留旧实现用于排查，正式实验还直接对比 upstream/。
reference = cc.compute_communication_probability(
    prepared_cellchat.copy(), engine="legacy", n_boot=100, seed_use=1
)
```

建议安装 `development/` 的 `accelerate` 可选依赖以使用 Numba 编译的稀疏
扫描。没有该编译器仍可计算，但纯 Python 大规模执行可能明显较慢。

# 论文定位与当前证据

建议题目：**保持 CellChat 计算定义的大规模、低内存通讯推断**。

这次开发已经形成可运行的计算引擎、与固定发布版的独立数值对照、完整教程
执行框架和真实/合成规模实验。结果见 `RESULTS.md`；算法见 `METHOD.md`。
研究对象应明确为 CellChat 的细胞群通讯推断阶段。

## 可以形成论文主体的技术内容

1. **跨标签置换复用稀疏顺序统计。** 表达值不变，按基因排序只需一次；
   每次标签置换中，各群体的非零表达仍是这个排序的有序子序列。隐式零
   通过秩区间处理，无需展开。沿用原分位数插值分支，避免严格 P 值比较
   对浮点舍入差异敏感的问题。
2. **置换中间结果的流式生命周期。** 每次只保留一个置换及其群体摘要，
   对 LR 分块计算并累计超越次数。内部置换相关内存不随置换次数线性增加，
   同时保留原 RNG 序列和严格 `P_boot > P_observed` 计数。
3. **模型依赖的静态编译。** 从 LR、复合物及辅因子构造依赖闭包并复用
   查表结果。全局归一化尺度在裁剪前确定，因此裁剪不改变公式输入。
   这项优化的实际收益应由消融验证，不能假定所有输入都会提速。

第一项最适合放在方法主体；后两项构成可扩展执行方案。
“不改变定义”是需要验证的设计约束，不应被写成新的生物学模型。

## 等价性的论证顺序

- 固定输入、数据库、类别顺序、随机种子/外部置换及依赖版本。
- 证明裁剪保留了全部模型依赖，并保留裁剪前的全局最大值。
- 证明群体有序子序列和隐式零秩给出与完整向量相同的分位数端点，
  再核对插值的实际浮点运算顺序。
- 证明每个置换的概率公式和严格超越判断不变；流式计数只改变存储方式。
- 用独立导入的固定 GitHub 源码作 oracle，验证概率、P 值、显著性、
  下游网络和存储往返。完整教程提供实际工作流覆盖。

设细胞数 N、有效基因数 G、细胞群数 K、非零表达数 Z、LR 数 L、置换次数 B。
**对于稀疏 triMean/median 路径和内部生成的置换**，排序准备后主要置换成本
约为 `O(B*(Z + G*K + N + L*K²))`，推断循环工作内存约为
`O(Z + N + G*K + L*K²)`。这不是所有平均方法的共同复杂度：密集输入及
均值方法使用分块回退，仍需遍历实际群体表达向量；外部置换还需逐列验证，
其中 `np.unique` 有 `O(N log N)` 的排序时间上界。

预处理的峰值还要计入裁剪前的全部 signaling 表达。若其非零条目数为 Z₀、
基因数为 G₀，稀疏提取、归一化和格式转换会另占 `O(Z₀ + G₀ + N)` 空间；
密集表达的归一化副本则为 `O(N*G₀)`。上述内存界限不含调用者额外提供的
N×B 置换矩阵。原输入及最终网络仍占空间，不能声称常数内存或已经支持
磁盘外存计算。

## 实验叙述应遵守的边界

| 证据 | 可以支持 | 不应外推为 |
|---|---|---|
| 固定 Python 发布版数值对照 | 同输入/同环境下兼容该实现 | 任意 R 版本逐位一致 |
| 完整公开教程 | 这些工作流的可运行性和被比较结果的一致性 | 全部潜在 API/输入永不出错 |
| 真实 68,579 细胞 PBMC | 一个完整真实数据集上的推断性能 | 多组织图谱的普遍倍数 |
| 十万/百万合成规模实验 | 对应稀疏度、群数和 LR 数的规模行为 | 百万细胞真实生物学发现 |
| 核时间与 RSS | 推断阶段性能和内存 | 差异筛选、绘图等全流程同倍数加速 |
| 小规模消融 | 当前设置下各执行优化的贡献 | 各项优化的收益可直接相加 |

真实 PBMC 性能实验使用固定的计算分组和完整可测候选 LR；不把这些分组
宣称为经过生物学验证的细胞类型注释。不同算法筛选不同 LR 或改变
平均表达/置换规则时，不能把时间差全部归于相同计算问题的加速。

## 投稿前仍需补足

- 对稀疏分位数、固定表达下的标签置换、其他 CellChat Python 实现进行
  文献及源码比较；本次实现和测试不构成首创性检索结论。
- 增加原 R CellChat 与有代表性的 Python 实现的性能基线，并明确其版本、
  线程数、相同候选 LR 和置换设置。当前相对本项目旧 Python 版的倍数，
  不能代替对领域现有实现的比较；这是评价论文加速贡献的关键实验。
- 在空闲机器上做多次独立重复，并增加另一平台/依赖版本的数值验证。
  单次真实大数据配对结果只能报告为一次实测。
- 系统改变 N、B、稀疏度、K 和 L。当前扩大 N 的合成实验固定群数和
  LR 数，尚不能验证 K 增长带来的平方输出成本。
- 补充不同组织与表达稀疏度的真实数据，分开报告冷编译、缓存启动和
  热执行。完整流程收益可能受未优化的中心性、NMF、UMAP 等步骤限制。
- 对照版本、硬件、输入、线程、预处理、参数、超时和内存上限应公开。
  原版超限时报告超限，不构造不存在的完整时间或一致性证据。

当前结果适合作为算法工程论文的研究原型和初步证据。发表强度取决于
上述比较、可复现性和真实应用覆盖；不能仅用 Python 移植或一个加速倍数
推定创新性已经充分。
